# New7z 右键菜单设计 · v0.1

设计日期：2026-11-03；实现更新：2026-11-04。HTML 场景原型保留；Windows 11 资源管理器现代菜单已实现并在本机当前用户注册。本文应用内菜单部分仍为设计范围，资源管理器实测见 [验收记录](Explorer右键验收.md)。

入口：[菜单场景原型](../prototype/context-menu-design.html)、[应用原型](../prototype/index.html)。前者比较 8 种场景，后者支持在实际示例列表中右键和通过「更多」打开菜单。

## 1. 设计原则

菜单随选择范围改变，命令采用明确动词。频繁使用的解压、预览继续保留在主命令栏，右键不是唯一入口。包内文件仍只读，不显示尚未实现的删除、重命名、剪切、粘贴或更新操作。

视觉沿用现有 Fluent 层级：轻表面、细描边、小圆角、短暂浮层阴影；不将品牌渐变铺满菜单，不为每项添加独立彩色方块。文字说明为主，图标用于扫描。包内的「复制文件名 / 复制包内路径」只复制文本，不使用“复制”图标横条冒充可以复制实际文件。

## 2. 应用内菜单

### 单个图片 / 文本

```text
┌ 项目封面.png ────────────────────┐
│ ◉  预览                          │
│ ↓  解压到…                       │
│ ──────────────────────────────── │
│ ▢  复制文件名                    │
│ ↗  复制包内路径                  │
│ ──────────────────────────────── │
│ ⓘ  属性                          │
└──────────────────────────────────┘
```

「预览」复用现有只读预览窗口。「解压到…」保留选中条目并打开已有解压设置。文件大小超过预览限制时仍可进入预览，显示原因与解压入口；不是在菜单里悄悄解压或启动外部程序。

PDF、Office、FIG、可执行文件等暂不支持的类型，将「预览」禁用并显示“仅支持图片与纯文本”。其他命令仍可用。只有真正缺失的读取能力才隐藏相关入口，不以扩展名图标证明格式支持。

### 文件夹

第一项改为「打开文件夹」，之后为「解压到…」「复制文件名」「复制包内路径」「属性」。解压范围包括子目录与条目；复制路径只复制当前文件夹的虚拟路径，不枚举全部子项。

### 多选

```text
┌ 已选择 3 项 ─────────────────────┐
│ ↓  解压选中的 3 项…              │
│ ──────────────────────────────── │
│ ▢  复制文件名                    │
│ ↗  复制包内路径                  │
│ ──────────────────────────────── │
│ ⓘ  查看所选属性                  │
└──────────────────────────────────┘
```

不显示单文件预览或打开。复制命令按可见排序逐行输出；包内路径使用 `项目素材.7z!/设计稿/界面预览.png`，明确是归档内定位，不假装存在已解压的本地文件。

### 空白区域

「全部解压…」「测试完整性」；分隔后「返回上一级」「全选」；再分隔后「按名称排序」「按大小排序」。排序项显示当前状态与可访问选中标记，重选当前项保持升序；需要倒序时使用列表列头。根目录的「返回上一级」禁用并说明原因。空列表或无结果时全选禁用；整体解压/测试针对整个归档而非搜索结果。

## 3. Windows 资源管理器菜单

系统主菜单中只提供一个 New7z 入口，子项由系统菜单组件绘制。场景原型展示的是该子菜单展开后的设计，不覆盖 Windows 的复制、分享、删除等既有命令。

### 单个压缩包

```text
New7z ›
  用 New7z 打开
  ─────────────────────────
  智能解压
  解压到…
  解压到当前文件夹
  ─────────────────────────
  测试完整性
```

同名文件夹名称来自归档文件名，并正确处理 `.tar.gz` 等复合后缀。第一版 Shell 可先覆盖已验证的 7z/ZIP；RAR 等由实际引擎格式表与验收结果开放。未知格式或读取失败进入主程序反馈，不能在 Explorer 构建菜单时同步尝试解压。

「智能解压」替换原「解压到同名文件夹」快捷动作：包内只有一个顶层文件或文件夹（含隐式目录）时直接解压到源包所在目录，保留包内路径，避免多套一层；多个顶层项目或空包使用同名文件夹。同名目录存在时沿用原合并规则，文件冲突默认自动改名保留两者。「解压到…」进入完整设置；「解压到当前文件夹」按用户指定目录输出。源包不会自动删除。目录判断在任务读取归档后进行，不在 Explorer 菜单展开时读取内容。

### 普通文件 / 文件夹

```text
New7z ›
  新建压缩包…
  ─────────────────────────
  压缩为 7Z
  压缩为 ZIP
  压缩为 TAR
```

快捷打包使用标准级别、不设密码；7Z 与 ZIP 可选择密码和级别，TAR 仅打包、不压缩也不支持密码。设置密码、压缩级别、输出目录必须进入新建压缩窗口。多个来源合并到一个归档，名称默认取共同父目录；无明确共同目录时用“归档.7Z / 归档.ZIP / 归档.TAR”。目标存在时自动添加编号，决不将“快速压缩”解释为覆盖更新旧包。

### 多个压缩包

「智能解压」「解压到…」「测试所选压缩包」。智能解压逐包判断顶层结构；需要同名文件夹的包沿用唯一目录分配。批量「解压到…」仍为每包一个子文件夹。任务按包串行，错误/密码分别处理，不将 A 包密码自动用于其他包。

### 混合选择

普通文件、文件夹与归档混选时，提供和普通文件相同的打包命令。归档作为原始文件加入新包，不自动展开，不只解压其中一部分并忽略其他来源。资源管理器文件夹空白处首版不增加 New7z 菜单，避免挤占系统菜单；应用内的空白菜单单独设计。

## 4. 选择、键盘与关闭规则

| 输入 | 行为 |
|---|---|
| 在未选中的文件上右键 | 先切换为该单项，再生成菜单 |
| 在多选集合中的条目上右键 | 保留整个选择集 |
| 在列表空白处右键 | 清空选择，显示归档/视图菜单 |
| 通过主命令栏「更多」 | 使用当前选择，不隐式清空 |
| Shift+F10 / 菜单键 | 以当前焦点条目为锚点；已有多选时保留 |
| ↑ / ↓ / Home / End | 跳过禁用项，移动菜单焦点 |
| Enter / Space | 执行当前命令；执行前关闭菜单 |
| Escape | 关闭菜单，回到触发控件 |
| Tab / Shift+Tab | 关闭菜单，移到页面相邻可聚焦控件 |
| 点击外部、滚动页面、窗口变更 | 关闭菜单；外部点击不抢回焦点 |

输入框与只读文本框保留自身的系统文字菜单，不用文件菜单替换。移动/触控通过可见「更多」按钮访问相同命令。菜单宽度随窗口收缩，靠边自动避让，菜单过长时自身滚动，不推挤文件列表。标题截断时可在“属性”中读取完整名称。

## 5. 视觉与组件规格

| 项目 | 规格 |
|---|---|
| 表面 | 浅/深主题语义 surface；正式 WinUI 短暂浮层采用系统 Acrylic/实色降级 |
| 宽度 | 默认 284 CSS px 原型；原生目标约 260–300 DIP，根据本地化文案自适应 |
| 菜单行 | 最低 38 px，13–14 px 文字，17–18 px 单色图标 |
| 形状 | 8 px 浮层、4 px 命令 hover 圆角，与项目 token 对齐 |
| 分组 | 主要动作 / 文本复制 / 属性；分隔仅表达动作类别 |
| 提示 | 顶部显示文件名或选择数量，不把整份路径塞入菜单 |
| 状态 | hover、focus、pressed、disabled、当前排序；禁用原因用文字，不能只靠灰色 |
| 层级 | 菜单为非模态轻关闭浮层；启动预览/确认前关闭，不与模态争抢焦点 |

HTML 原型的共享 owner 为 `context-menu.js`，应用适配在 `context-menu-app.js`；场景工作台复用同一命令定义，避免两套文案。原生实现拟新增共享 `ContextCommandService`：通过当前选择快照生成命令，绑定现有 `ShowPreviewAsync`、`ExtractDialogAsync` 和任务服务。文字复制走系统剪贴板并反馈失败。

## 6. 原生与 Shell 实现边界

应用内使用 WinUI `CommandBarFlyout` / `MenuFlyout`，将现有预览、解压、属性等命令作为共享 secondary commands；不会在 UI 层拼接另一个压缩命令行。[Microsoft 菜单指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/menus-and-context-menus)

Windows 11 现代 Explorer 菜单需要本应用的 `IExplorerCommand` COM 扩展及应用身份。当前未打包 EXE 可选择 sparse package 方式关联扩展，不能把简单文件关联视为现代右键集成。壳扩展只接收选择和分发请求，长耗时读取/压缩转交主程序；不能卡在 Explorer 菜单构建路径上。[Microsoft Shell 集成说明](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)

已接入：`native/New7z.Shell.cpp` 实现 `IExplorerCommand`，通过受控本地 JSON 请求传递动作与完整路径列表，不拼接终端命令。`New7z.ShellHost.exe` 启动应用，`ShellRequest.cs` 校验请求路径、大小与来源文件，再复用真实引擎。压缩、解压和测试由独立 `ShellTaskWindow` 执行，不构造主界面；只有打开归档才进入主窗口。设置与密码在小窗口中完成，不写入请求或命令行。小窗口按用户要求去除系统标题栏，保留可拖动内容头部和底部关闭。菜单图标直接引用 Shell DLL 嵌入的 Logo 资源。注册与移除通过 `scripts/register-shell.ps1`，正式签名安装流程尚待完成，不要求安装 7-Zip。

当前原生命令使用稳定文案「智能解压」「压缩为 7Z」「压缩为 ZIP」「压缩为 TAR」，扩展名统一大写，未在菜单文字中插入完整文件名；单个快捷压缩取来源名称，多选默认「归档」，目标存在时自动编号。智能解压保留原 `extract-named` 命令与设置位，升级后沿用用户勾选状态。归档入口按扩展名快速分类，实际支持与文件错误由主程序反馈，菜单展开不读取归档。RAR 等格式尚缺完整样本验收，不将菜单可见视为格式已验证。

## 7. 验收重点

应用内原型检查右键不丢多选、对未选中文件右键切换单选、空白清空选择、菜单键/Shift+F10、方向键与禁用项、Escape 恢复、触控等效入口、边缘避让、长中文文件名、浅深主题、200% 缩放；命令触发与主工具栏结果相同。复制应按界面排序，失败提供手动复制；批量操作逐项反馈。Explorer 已实机验证菜单展开、ZIP 创建与 7z 解压；多 DPI、其他系统版本及 RAR 样本仍需补充验收。
