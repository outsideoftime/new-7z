# New7z 0.1.28 安装包

日期：2026-11-10。自有代码 MIT，第三方组件保留原许可。

[GitHub Releases](https://github.com/outsideoftime/new-7z/releases) 提供 Windows 11 x64 安装器、SHA256SUMS.txt 与逐文件 release-manifest.json。0.1.28 安装 EXE 约 **23.35 MiB**（24,484,919 字节），运行文件约 **76.78 MiB**（80,510,258 字节，180 个文件），SHA-256 见 `SHA256SUMS.txt`；首次安装另有约 5.22 MiB 安装/卸载组件。

## 0.1.28 更新

- 资源管理器右键菜单新增「压缩为 TAR」；普通文件、文件夹和多选均可直接创建 `.tar`。TAR 仅打包，不压缩，也不支持密码。
- 右键菜单中的格式名统一为大写：「压缩为 7Z / ZIP / TAR」，设置页的命令名称同步。
- 设置新增「默认压缩格式」和「默认压缩方法」：格式可选 7z/ZIP/TAR；7z 方法可选 LZMA2、LZMA、BZip2、PPMd、Deflate、存储，ZIP 方法可选 Deflate、Deflate64、BZip2、LZMA、PPMd、存储。主界面「新建压缩」与右键「新建压缩包…」按这些默认值预选；TAR 时自动禁用密码、压缩级别和方法。
- 旧版菜单配置 `Commands=255`（当时的全部命令）会迁移为 511，升级后 TAR 命令默认可见；用户主动取消勾选后保持关闭。
- TAR 文件类型关联与格式图标沿用原有 `.tar` 支持，不需要重新注册关联。

## 0.1.27 更新

- 修复安装版点击「全部解压」或其他进入任务中心的操作闪退：裁剪构建会移除 WinRT.Runtime 中通过反射解析的 ABI 辅助类型，任务卡片绑定 `DataContext` 时抛空引用；现通过 `TrimmerRoots.xml` 保留 WinRT.Runtime 全部成员。
- 多选压缩不再统一使用「归档」：右键压缩为 7z/ZIP、「新建压缩包…」和应用内新建压缩改用所选内容的最近共同父目录名，跨盘或无共同目录时才回退「归档」。
- 设置新增「压缩文件图标」：7z、ZIP、RAR、TAR、GZ、BZ2、XZ、ISO 可分别替换 PNG 并恢复默认，用于「最近使用」等应用内显示，不修改资源管理器文件关联图标。
- 「全部解压」和「解压选中」改为打开与右键任务相同的独立小窗口，不再切换到任务中心；任务窗口和任务中心都显示百分比，任务完成后进度条固定为 100%。
- 修复文件夹拖动解压：拖到资源管理器时文件夹会被忽略；现在文件夹连同内部内容一起复制。
- `--verify-ui` 增加任务页绑定检查，防止裁剪配置回归。

## 体积变化

Windows App SDK 的总包曾带入未使用的 AI/ML 等运行组件。现直接依赖 WinUI 组件包，使用自包含 .NET 的部分裁剪，并提高安装器压缩等级。每次构建使用全新 payload 目录，防止旧 DLL 混入。保留 .NET、WinUI、本地引擎、完整许可与 7-Zip 源码，仍可离线运行。0.1.9 起发布流程还会移除 .NET 调试组件（`mscordaccore`、`mscordbi`、`DiaSymReader`）和 zh-CN/en-US 之外的 WinUI 语言资源，并把 Logo 与格式图标缩到实际显示所需尺寸；固实压缩下这些文件的安装包收益有限，但能明显减少解包后的运行文件体积。

裁剪保留 New7z.App、New7z.Core 全部代码和 JSON 源生成上下文，并通过 `TrimmerRoots.xml` 保留 WinRT.Runtime 全部成员：CsWinRT 依赖反射解析 ABI 辅助类型，裁剪后会把 XAML 绑定对象（如任务卡片）的 DataContext 编组变成 NullReferenceException。Microsoft.Windows.SDK.NET 仍有 IL2104 裁剪警告；已做实际发布版启动/设置/图片/文本/任务检查，但未覆盖所有 Windows 配置。可用 `build-installer.ps1 -Untrimmed` 构建对照。

## 安装和升级

默认位置 `%LOCALAPPDATA%\Programs\New7z`，当前用户安装，无需另装运行库或完整 7-Zip。创建开始菜单入口，桌面入口可选，菜单与文件关联任务默认勾选。

程序放在 `Versions\<版本>-<内容哈希>`。升级保留旧运行目录，避免覆盖仍被 Explorer 或任务加载的 DLL，因此已有安装的总目录体积可能包括旧版；新版本运行文件体积与整个升级目录体积应分别计算。不会强制结束资源管理器或用户任务。应用设置、最近记录和 New7z 菜单偏好在安装目录外，升级与卸载保留；卸载时会把「隐藏 Windows 压缩菜单」重置为关闭并恢复 New7z 曾修改的 Windows「压缩到」菜单项。

通过 Windows「已安装的应用」或 `Uninstall\unins000.exe` 卸载。仅移除该安装拥有的注册与文件；如 New7z 设置曾隐藏 Windows「压缩到」菜单，卸载时会恢复它修改前的当前用户设置。安装过程本身不修改 Windows 自带压缩命令，不强行设置文件默认程序，不自动导入证书或开启开发者模式。

## 右键菜单修复

0.1.5 在现代身份注册成功时没有同时注册兼容入口，部分机器因此无可用菜单。0.1.6 勾选菜单任务后**始终注册兼容菜单**，使用独立 CLSID，避免和现代 COM 注册冲突，并调用 SHChangeNotify 通知系统刷新。0.1.20 起改为二选一：现代菜单注册成功时不再注册兼容菜单，避免资源管理器同时出现两个 New7z；只有现代注册不可用时才退回兼容菜单。设置中的「修复右键菜单注册」按当前模式处理，不会补出第二份。

入口：右键文件/文件夹 → **显示更多选项 → New7z**。设置 → 资源管理器右键菜单 → **修复右键菜单注册** 可重新注册。可见性与命令集合沿用现有用户偏好；关闭总开关时修复不会替用户打开开关。

现代菜单在受信任身份包可用，或系统已具备开发注册条件时额外提供。当前发行未进行受信任发布者签名，不能承诺在所有机器上显示首层现代菜单。微软说明：[为非打包应用授予身份](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps)。

## 文件关联

0.1.6 增加 HKCU Capabilities、RegisteredApplications、ProgID 和扩展名 OpenWithProgids 注册，支持 `.7z`、`.zip`、`.rar`、`.tar`、`.gz`、`.xz`、`.bz2`、`.iso`。安装后可在 Windows「默认应用」找到 New7z，也可在压缩包「打开方式」选择。0.1.8 起每种格式使用独立 ProgID（`New7z.7z`、`New7z.zip` 等）和 `Assets\Formats` 下的格式图标，未再为所有格式共用一个 ProgID。

如之前已经把 New7z 设为某个格式的默认程序，Windows 保存的是旧的 `New7z.Archive` 选择；需要在「默认应用」中重新选择一次，才会使用新的按格式图标。

应用设置 → 文件关联 → **注册 / 修复文件关联**；**选择默认应用** 使用 Windows 默认应用页面，由用户确认格式。注册脚本不改写 UserChoice，不强制抢占默认程序。卸载移除该安装拥有的关联能力与打开方式条目。

## 自动更新

应用启动时读取 `https://api.github.com/repos/outsideoftime/new-7z/releases/latest`，取 tag 版本号与资产 `New7z-<版本>-x64-Setup.exe`。下载完成后与同版本 `SHA256SUMS.txt` 比对；校验失败的包会被删除且不会运行。安装前会询问用户，确认后应用退出，再由延迟启动的安装器以 `/SILENT` 完成升级。发布时请保持资产命名不变并同时上传 `SHA256SUMS.txt`，否则更新会被拒绝。

自动检查默认开启，可在设置 → 应用更新关闭或手动检查；更新只访问 GitHub 域名，不上传本地文件或文件名。安装包未签名时仍可能出现系统 SmartScreen 提示；SHA-256 校验只证明下载文件与发布清单一致，不代表发布者身份已由证书认证。

## 构建与验证

```powershell
./scripts/get-build-tools.ps1
./scripts/build-installer.ps1
# 也可指定已有编译器
./scripts/build-installer.ps1 -IsccPath 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe'
```

Inno Setup 6.7.4 来自官方发布，下载脚本验证固定 SHA-256 与 Pyrsys B.V. 签名。翻译来自官方 issrc 仓库并保留原维护者信息。签名仅在显式传入 `-SigningCertificateThumbprint` 时启用，身份发布者须匹配 CN=New7z。
