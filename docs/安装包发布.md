# New7z 1.0.4 安装包

日期：2026-11-14。自有代码 MIT，第三方组件保留原许可。

[GitHub Releases](https://github.com/outsideoftime/new-7z/releases) 与 [Gitee 镜像](https://gitee.com/wgliangzero/new-7z/releases) 提供 Windows 11 x64 安装器、SHA256SUMS.txt 与逐文件 release-manifest.json。1.0.4 安装 EXE 约 **23.63 MiB**（24,775,677 字节），运行文件约 **77.80 MiB**（81,573,825 字节，243 个文件），BuildId `a547a70da33d`，SHA-256 见 `SHA256SUMS.txt`；首次安装另有约 5.22 MiB 安装/卸载组件。

## 1.0.2 更新

- 引擎隔离：列表、读取、预览、创建、修改、测试和解压改由独立进程 `New7z.EngineHost.exe` 执行，界面进程不再加载 `7z.dll`；工作进程异常终止时清理独占临时文件，并在下一次操作时自动重启。该进程受 Job Object 约束，单个工作进程内存上限 2 GiB。
- 不可信归档防护：拒绝 TAR 符号/硬链接与 ZIP POSIX 符号链接，检查重解析目标；默认最多 1,000,000 条目、单文件 64 GiB、累计输出 100 GiB，使用无符号溢出安全累加，损坏或取消时回滚；临时输出提交前复制 `Zone.Identifier`，保留下载来源标记并传播到嵌套归档。
- 签名发布门禁：`build-installer.ps1` 新增 `-RequireSignature -SigningCertificateThumbprint <指纹>`，校验证书私钥、信任链与代码签名用途，身份包 Publisher 使用实际证书主题，附 RFC 3161 时间戳并验证签名；安装、修复和启动检查身份包实际签名，失败时退回兼容菜单。当前尚无正式证书，本轮发布包未签名。
- 列表与属性：支持按名称、大小、压缩后大小、修改时间升序/降序排序，文件夹优先、未知值在后，排序与搜索保留选择；新增窄窗口属性对话框与属性栏汇总。
- 新增扩展格式：`.zst`（Zstandard）与 `.lz4` 标准流支持创建、列举、预览、解压和校验，仅单文件、不支持密码。
- 界面细节：42 种文件类型图标按扩展名显示并缓存；目录切换复用虚拟化列表，取消插入/删除过渡，搜索合并与输入法处理，任务卡片原位更新，共享文件后台读写。
- 版本号提升为 1.0.2。详见 [稳定性与安全加固](稳定性与安全加固.md)。

## 1.0.1 更新

- 解压改为一次打开归档、批量输出：普通解压、应用内选中条目解压和右键任务共用同一批量流程，不再为每个文件重新解析压缩包，固实 7z 也不重复解码。实测 RAR（5,858 个文件）从 194.482 秒降到 14.687 秒，512 文件、32 MiB 样本的 ZIP / 固实 7z / TAR 分别从 1.418 / 11.154 / 3.896 秒降到 0.626 / 0.615 / 0.601 秒。详见 [解压性能优化](解压性能优化.md)。
- 保留逐文件 CRC 成功后再提交、冲突处理、路径预检与取消清理；进度通知限制为约每 50 ms 一次，修改时间通过已打开的输出句柄设置，路径重解析点检查合并为一次文件属性查询。

## 体积变化

Windows App SDK 的总包曾带入未使用的 AI/ML 等运行组件。现直接依赖 WinUI 组件包，使用自包含 .NET 的部分裁剪，并提高安装器压缩等级。每次构建使用全新 payload 目录，防止旧 DLL 混入。保留 .NET、WinUI、本地引擎、完整许可与 7-Zip 源码，仍可离线运行。0.1.9 起发布流程还会移除 .NET 调试组件（`mscordaccore`、`mscordbi`、`DiaSymReader`）和 zh-CN/en-US 之外的 WinUI 语言资源，并把 Logo 与格式图标缩到实际显示所需尺寸；固实压缩下这些文件的安装包收益有限，但能明显减少解包后的运行文件体积。

裁剪保留 New7z.App、New7z.Core 全部代码和 JSON 源生成上下文，并通过 `TrimmerRoots.xml` 保留 WinRT.Runtime 全部成员：CsWinRT 依赖反射解析 ABI 辅助类型，裁剪后会把 XAML 绑定对象（如任务卡片）的 DataContext 编组变成 NullReferenceException。Microsoft.Windows.SDK.NET 仍有 IL2104 裁剪警告；已做实际发布版启动/设置/图片/文本/任务检查，但未覆盖所有 Windows 配置。可用 `build-installer.ps1 -Untrimmed` 构建对照。

## 安装和升级

默认位置 `%LOCALAPPDATA%\Programs\New7z`，当前用户安装，无需另装运行库或完整 7-Zip。创建开始菜单入口，桌面入口可选，菜单与文件关联任务默认勾选。

程序放在 `Versions\<版本>-<内容哈希>`。升级保留旧运行目录，避免覆盖仍被 Explorer 或任务加载的 DLL，因此已有安装的总目录体积可能包括旧版；新版本运行文件体积与整个升级目录体积应分别计算。不会强制结束资源管理器或用户任务。应用设置、最近记录和 New7z 菜单偏好在安装目录外，升级与卸载保留；卸载时会把「隐藏 Windows 压缩菜单」重置为关闭并恢复 New7z 曾修改的 Windows「压缩到」菜单项。

通过 Windows「已安装的应用」或 `Uninstall\unins000.exe` 卸载。仅移除该安装拥有的注册与文件；如 New7z 设置曾隐藏 Windows「压缩到」菜单，卸载时会恢复它修改前的当前用户设置。安装过程本身不修改 Windows 自带压缩命令，不强行设置文件默认程序，不自动导入证书或开启开发者模式。

## 右键菜单修复

0.1.5 在现代身份注册成功时没有同时注册兼容入口，部分机器因此无可用菜单。0.1.6 勾选菜单任务后**始终注册兼容菜单**，使用独立 CLSID，避免和现代 COM 注册冲突，并调用 SHChangeNotify 通知系统刷新。0.1.20 起改为二选一：现代菜单注册成功时不再注册兼容菜单，避免资源管理器同时出现两个 New7z；只有现代注册不可用时才退回兼容菜单。设置中的「修复右键菜单注册」按当前模式处理，不会补出第二份。

入口：右键文件/文件夹 → **显示更多选项 → New7z**。设置 → 资源管理器右键菜单 → **修复右键菜单注册** 可重新注册。可见性与命令集合沿用现有用户偏好；关闭总开关时修复不会替用户打开开关。

现代菜单在受信任身份包可用，或系统已具备开发注册条件时额外提供。当前发行未进行受信任发布者签名，不能承诺在所有机器上显示首层现代菜单。微软说明：[为非打包应用授予身份](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps)。

## 文件关联

0.1.6 增加 HKCU Capabilities、RegisteredApplications、ProgID 和扩展名 OpenWithProgids 注册，支持 `.7z`、`.zip`、`.rar`、`.tar`、`.gz`、`.xz`、`.bz2`、`.iso`。安装后可在 Windows「默认应用」找到 New7z，也可在压缩包「打开方式」选择。0.1.8 起每种格式使用独立 ProgID（`New7z.7z`、`New7z.zip` 等）和 `Assets\Formats` 下的格式图标，未再为所有格式共用一个 ProgID。

如之前已经把 New7z 设为某个格式的默认程序，Windows 保存的是旧的 `New7z.Archive` 选择；需要在「默认应用」中重新选择一次，才会使用新的按格式图标。

应用设置 → 文件关联 → **注册 / 修复文件关联**；**选择默认应用** 使用 Windows 默认应用页面，由用户确认格式。注册脚本不改写 UserChoice，不强制抢占默认程序。卸载移除该安装拥有的关联能力与打开方式条目。

## 自动更新

应用启动时优先读取 `https://api.github.com/repos/outsideoftime/new-7z/releases/latest`，取 tag 版本号与资产 `New7z-<版本>-x64-Setup.exe`；GitHub API 受限或网络失败时改读 GitHub Releases Atom 源，仍失败则读取 Gitee 镜像的 Release 列表 `https://gitee.com/api/v5/repos/wgliangzero/new-7z/releases`。Gitee 的 `latest` 按创建时间排序，补发旧版本会让新版本不再排在第一位，因此这里读取列表并选择版本号最高的一项。下载优先使用 GitHub 资产地址，失败时改用 Gitee 同版本资产；校验文件同样先 GitHub 后 Gitee。下载完成后与同版本 `SHA256SUMS.txt` 比对；校验失败的包会被删除且不会运行。安装前会询问用户，确认后应用退出，再由延迟启动的安装器以 `/SILENT` 完成升级。发布时请保持资产命名不变，并在 GitHub 和 Gitee 同时上传 `New7z-<版本>-x64-Setup.exe` 与 `SHA256SUMS.txt`，否则对应通道的更新会被拒绝。

## Gitee 镜像发布

Gitee 仓库 `wgliangzero/new-7z` 自动镜像 GitHub 的提交和标签，但 Release 需要单独创建。上传安装包、`SHA256SUMS.txt` 与 `release-manifest.json`：

```powershell
$env:GITEE_TOKEN='<Gitee 私人令牌>'
./scripts/publish-gitee-release.ps1            # 当前版本，读取 artifacts/releases
./scripts/publish-gitee-release.ps1 -Tag v1.0.3   # 补发历史版本
```

脚本幂等：Release 已存在时只补传缺失的资产。私人令牌在 Gitee「设置 → 私人令牌」生成，勾选 `projects` 权限；令牌只在本机使用，不写入仓库。

自动检查默认开启，可在设置 → 应用更新关闭或手动检查；更新只访问 GitHub 域名，不上传本地文件或文件名。安装包未签名时仍可能出现系统 SmartScreen 提示；SHA-256 校验只证明下载文件与发布清单一致，不代表发布者身份已由证书认证。
